# コーディングデータの使い方

このフォルダは、Webサイトを編集・確認するためのコーディングデータです。

HTML、Sass、JavaScript、画像を編集すると、ローカル環境（自分のMacの中）でWebサイトを確認できます。

この説明は、コーディング環境を初めて使う方向けに、macOSを前提として記載しています。

## 最初に用意するもの

- Mac
- インターネット接続
- Google ChromeなどのWebブラウザ
- Visual Studio Codeなどのコード編集ソフト
- このコーディングデータ一式

## 初回のみ行う準備

### 1. ターミナルを開く

Macで `command + space` を押し、「ターミナル」と入力して起動します。

以降の灰色の枠内にあるコマンドは、ターミナルへ1行ずつ貼り付けて `return` キーを押してください。

### 2. nodebrewをインストールする

nodebrewは、Webサイトの開発に必要なNode.jsのバージョンを管理するためのツールです。

まず、次のコマンドを実行します。

```bash
curl -L git.io/nodebrew | perl - setup
```

続けて、nodebrewをターミナルから使えるようにします。

```bash
echo 'export PATH=$HOME/.nodebrew/current/bin:$PATH' >> ~/.zshrc
source ~/.zshrc
```

次のコマンドで、nodebrewが使用できることを確認します。

```bash
nodebrew help
```

英語のコマンド一覧が表示されれば準備完了です。

### 3. Node.jsをインストールする

このデータでは、Node.js `v22.23.4` を使用します。

```bash
nodebrew install-binary v22.23.4
nodebrew use v22.23.4
```

インストール後、次の2つを実行します。

```bash
node -v
npm -v
```

`node -v` の結果が `v22.23.4` になっていれば問題ありません。`npm -v` は数字が表示されれば大丈夫です。

### 4. ターミナルでコーディングデータのフォルダを開く

ターミナルへ次のように入力します。`cd` の後ろには半角スペースが必要です。

```bash
cd
```

まだ `return` キーは押さず、`cd` の後ろへ半角スペースを1つ入力します。続けて、Finderからこのコーディングデータのフォルダをターミナルへドラッグ＆ドロップします。

フォルダの場所が自動入力されたら、`return` キーを押してください。

正しいフォルダを開けているか、次のコマンドで確認できます。

```bash
pwd
```

表示された場所の末尾が、このコーディングデータのフォルダ名になっていれば問題ありません。

### 5. 必要なパッケージをインストールする

```bash
npm ci
```

完了まで数分かかる場合があります。処理が終わり、再び文字を入力できる状態になれば完了です。

警告として `npm WARN` や脆弱性の件数が表示される場合がありますが、途中で `npm ERR!` が表示されずに完了していれば、そのまま次へ進んでください。

`npm audit fix` や `npm audit fix --force` はファイル構成や動作が変わる可能性があるため、自己判断では実行しないでください。

## Webサイトを起動する

コーディングデータのフォルダをターミナルで開いた状態で、次のコマンドを実行します。

```bash
npm run dev
```

しばらくするとブラウザが自動で開きます。自動で開かない場合は、ブラウザで次のURLを開いてください。

```text
http://localhost:3000/
```

ターミナルで `npm run dev` が動いている間は、ファイルを保存するとブラウザへ変更が反映されます。

### Webサイトを終了する

`npm run dev` を実行しているターミナルを選び、`control + C` を押します。

ターミナルのウインドウを閉じる前に、この操作で終了してください。

## 2回目以降の起動方法

2回目以降は、nodebrewとパッケージのインストールは不要です。

1. ターミナルを開く
2. `cd` と半角スペースを入力し、コーディングデータのフォルダをドラッグ＆ドロップする
3. `return` キーを押す
4. `npm run dev` を実行する

Node.jsのバージョンが変わってしまった場合は、起動前に次のコマンドを実行してください。

```bash
nodebrew use v22.23.4
```

## 主に編集する場所

| 編集内容 | 編集する場所 | 補足 |
| --- | --- | --- |
| ページのHTML | `index.html` | ページの文章や構造を編集します |
| Sass | `src/sass/` | デザインやレイアウトを編集します |
| JavaScript | `js/` | 動きや操作処理を編集します |
| 画像 | `src/images/` | 保存すると圧縮画像が `images/` に出力されます |
| Swiperの設定 | `js/swiper.js` | スライダーの設定を編集します |

### Sassについて

Sassは必ず `src/sass/` の中を編集してください。

`css/styles.css` は起動中に自動生成されるファイルです。直接編集しても上書きされるため、編集しないでください。

`src/sass/styles.scss` もファイル一覧から自動生成されるため、原則として直接編集しません。

### 画像について

元画像は `src/images/` の中へ配置してください。

`npm run dev` の起動時と起動中に画像が圧縮され、公開用の `images/` フォルダへ出力されます。すでに出力済みで変更されていない画像は再処理されません。

### JavaScriptについて

JavaScriptはルート直下の `js/` フォルダを編集します。JavaScriptの自動圧縮は行いません。

SwiperはCSS・JavaScriptともにバージョン `8.4.3` を使用しています。

## よく使うコマンド

| コマンド | 内容 |
| --- | --- |
| `npm run dev` | 開発画面を起動し、Sass・画像・ブラウザ表示を自動更新します |

通常の編集作業で使用するのは `npm run dev` だけです。`npm run build` と `npm run preview` は公開データを確認するためのコマンドなので、制作担当者から指示がある場合だけ使用してください。

## フォルダについての注意

次のフォルダは自動生成されます。原則として直接編集しないでください。

- `node_modules/`：動作に必要なパッケージ
- `css/styles.css`：Sassから生成されたCSS
- `images/`：圧縮後の画像
- `dist/`：ビルドで生成される公開用データ

`node_modules/` が入っていない状態で受け取っても問題ありません。初回準備の `npm ci` を実行すると自動生成されます。

## 困ったとき

### `nodebrew: command not found` と表示される

次のコマンドを実行してから、もう一度試してください。

```bash
source ~/.zshrc
```

解決しない場合は、ターミナルを一度閉じて開き直してください。

### `node: command not found` または `npm: command not found` と表示される

次のコマンドを実行します。

```bash
nodebrew use v22.23.4
node -v
npm -v
```

### ブラウザが自動で開かない

ターミナルで `npm run dev` が動いていることを確認し、ブラウザで次のURLを開いてください。

```text
http://localhost:3000/
```

### `npm ci` または `npm run dev` で `npm ERR!` が表示される

次の3点を確認し、表示されたエラー文を省略せずに制作担当者へ共有してください。

```bash
node -v
npm -v
pwd
```

原因確認前にファイルの削除、パッケージの更新、`npm audit fix --force` は行わないでください。

## 制作時の前提

- スマートフォン向けの表示を基準に実装する、スマホファーストの環境です。
- サイズ指定は主に `rem` を使用します。
- Swiper 8.4.3、Vite 5、Dart Sassを使用しています。
